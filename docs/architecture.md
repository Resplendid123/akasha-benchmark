# 代码架构

本平台使用 React、FastAPI 和 SQLite。Akasha 负责远端编译与查询，本平台负责组织实验、保存结果和计算指标。

| 模块 | 职责 | 主要入口 |
| --- | --- | --- |
| 前端页面 | 表单、任务操作、结果展示 | `web/src/views/` |
| 前端公共代码 | HTTP 请求、响应类型、异步状态和基础控件 | `api.ts`、`types.ts`、`ui.tsx` |
| 后端路由 | 请求处理、配置读写、结果查询 | `src/akasha_platform/api/` |
| 任务管理 | 参数白名单、子进程启动、日志和停止操作 | `akasha_platform/tasks.py` |
| 数据处理 | 适配、归一化、子集、导入、查询和评测 | `src/akasha_benchmark/` |
| 存储 | SQLite 连接、迁移、记录操作和身份校验 | `akasha_benchmark/store/` |
| 外部客户端 | Akasha HTTP、模型 HTTP、只读 PostgreSQL | `akasha_client.py`、`judge/client.py`、`lineage.py` |

## 数据流

原始 JSON 经适配器转换为 `sample` 和 `corpus_doc`。归一化将数据集元信息、样本和语料作为一个事务更新。
编译层从指定数据集抽取 QA 和语料，保存到 `subset_sample`、`subset_doc`；Markdown 统一由 `CorpusDoc.to_markdown()` 渲染。
入库阶段保存远端页面映射和模型快照，查询阶段保存完整响应，评测阶段保存指标和汇总。
归因读取评测结果，可补充只读数据库链路及模型分析。

SQLite 是后续阶段的输入来源；JSONL、Markdown 和报告文件是可选导出。历史文件恢复由 `store.reindex` 处理。
文件导出和数据库迁移各自保留明确入口，不混入页面展示逻辑。

## 配置与状态

- Akasha 连接在本地 `connection` 表保存；测试连接使用已保存配置，workspace 由服务端解析。
- Akasha 模型配置通过 HTTP 在线读取和修改；本地索引层保存入库快照，用于配置漂移校验。
- 评估和归因共用 `JudgeClient`，通过 httpx 请求 `{base_url}/chat/completions`。模型根地址须包含服务商要求的版本路径。
- 连接密码显式传空会清除；本地评估/归因密钥传空会保留原值。密钥不参与模型身份哈希。
- 前端 `useAsync` 管理取数，`useAction` 管理用户触发的请求；卸载后不更新状态。提示文字不作为输入值。
- 路由通过 `db` / `writable` 上下文使用数据库，退出时关闭连接，写入异常时回滚未提交事务。

## 任务边界与限制

页面将实验参数提交到任务接口，后端按白名单存入 `run_config`，阶段 CLI 通过 `--run-config` 读取。
长时间的编译、查询和评测通过子进程执行；连接测试和单条归因等接口仍在请求内执行。

当前日志采集线程属于 Web 进程，阶段 stdout 使用管道。独立子进程不等于持久任务队列：
后端重启后不保证任务继续运行、日志继续采集或完成状态正确更新。开发热更新期间也适用此限制。
如果需要可靠的跨重启运行，应将任务执行及日志采集交给独立 worker，并设计任务状态恢复。

Markdown 文档包目前仅在适配器状态页预留，未注册为可执行适配器；QA 约定与导入实现尚未接入。
`store/repo.py` 仍集中包含多个领域的 SQL 操作；新增功能应按数据职责组织，避免继续向路由复制存储逻辑。
